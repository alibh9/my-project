# منصة حجز مواعيد مكيفات

موقع حجز مواعيد لمحل مكيفات: العميل يختار نوع المكيف واليوم والموعد ويرسل بياناته، ثم يصله تأكيد على واتساب. ولصاحب المحل لوحة إدارة لمتابعة الحجوزات وتعيين الفنيين والتقارير.

## التشغيل السريع

المتطلبات: **Node.js 22.13 أو أحدث** (تُستخدم SQLite المدمجة `node:sqlite`، فلا توجد بناءات أصلية).

```bash
npm install
cp .env.example .env        # عدّل القيم، وخصوصاً ADMIN_PASSWORD
node --env-file=.env server/index.js
```

- الموقع: http://localhost:3000
- لوحة الإدارة: http://localhost:3000/admin/ (مصادقة أساسية باسم `ADMIN_USER` وكلمة `ADMIN_PASSWORD`)
- الاختبارات: `npm test`
- أيقونات PWA: `npm run icons`

> إن لم تُضبط `ADMIN_PASSWORD` تبقى لوحة الإدارة معطّلة (503) عمداً.

## ما الذي يغطيه المشروع

| المتطلب | التنفيذ |
|---|---|
| نوع المكيف (سبلت، وندو، دكت، سنترال) | بطاقات اختيار في الخطوة الأولى، ويُخزَّن النوع مع الحجز |
| العنوان والموقع GPS ونسخ الإحداثيات | حقل عنوان نصي، وحقل إحداثيات يقبل `lat, lng` أو رابط Google Maps، وزر "موقعي الحالي"، وزر نسخ، ورابط للخريطة |
| تقويم يومي/شهري بحالة بصرية | شهري: أخضر متاح، أصفر جزئي، أحمر ممتلئ، رمادي غير متاح. واليوم المختار يعرض مواعيده الثلاثة |
| ثلاثة مواعيد ثابتة | 9:00 صباحاً، 12:00 ظهراً، 4:00 عصراً |
| منع الحجز المزدوج | معاملة `BEGIN IMMEDIATE` تتحقق من السعة وتُسنِد فنياً ثم تُدرج الحجز، ومعها فهرس فريد على (التاريخ، الموعد، الفني) كطبقة ثانية |
| رسالة واتساب للعميل عند الحجز | تتضمن الموعد ونوع المكيف والعنوان ورابط الخريطة |
| إشعار لصاحب المحل والفني | يُرسل فور تأكيد الحجز (وللفني إن كان مُسنداً) |
| لوحة إدارة | عرض وفلترة وتعديل الحالة والموعد والفني، إدارة الفنيين، تقرير يومي |
| تصدير CSV | `/api/admin/export.csv` مع BOM لقراءة العربية في Excel، وحماية من حقن الصيغ |
| تنبيهات قبل الموعد | مجدول كل دقيقة يرسل تذكيراً للعميل والفني قبل `REMINDER_MINUTES` دقيقة، مرة واحدة |
| واجهة متجاوبة و PWA | تصميم RTL متجاوب، و`manifest` و`service worker` يخزّنان الهيكل الأساسي |
| مصادقة أساسية للإدارة | Basic Auth مع مقارنة آمنة زمنياً، تشمل صفحة الإدارة وملفاتها |
| التحقق من المدخلات | الاسم والجوال (يُوحَّد إلى +E.164) والعنوان والإحداثيات والتاريخ والموعد |
| حماية من الحجز الآلي | تحدٍّ حسابي يُستهلك مرة واحدة ولا يُستهلك إلا إذا كانت بقية الحقول صحيحة، وحقل مصيدة مخفٍ، وحد معدل لكل IP |

## إعداد واتساب

`WHATSAPP_PROVIDER` يختار المزوّد:

- `log` (الافتراضي): يطبع الرسائل في الكونسول، مناسب للتجربة.
- `twilio`: يحتاج `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_WHATSAPP_FROM`.
- `meta`: WhatsApp Cloud API ويحتاج `META_WHATSAPP_PHONE_NUMBER_ID` و`META_WHATSAPP_TOKEN`.

**ملاحظة:** واتساب لا يسمح برسائل تبدأ بها أنت (business-initiated) خارج نافذة 24 ساعة إلا عبر **قوالب معتمدة**.

لإرسال تأكيد الحجز عبر قالب Meta المعتمد:

1. أنشئ قالباً في Meta Business Manager بسبعة متغيرات في النص بالترتيب: الاسم، رقم الحجز، التاريخ، الموعد، نوع المكيف، العنوان، رابط الخريطة.
2. بعد اعتماده اضبط `META_TEMPLATE_CUSTOMER_CONFIRMATION` باسم القالب و`META_TEMPLATE_LANGUAGE` بلغته (مثلاً `ar`).

إن لم يُضبط اسم القالب يُرسل نص حر، وهذا يعمل ضمن نافذة 24 ساعة فقط. تُحفظ حالة كل إرسال في الحجز (`notify_status`) وتظهر في لوحة الإدارة.

### قرارات تصميمية

- **السعة:** كل موعد يتسع لعدد الفنيين النشطين. مع فني واحد يُقبل حجز واحد في الموعد، ومع ثلاثة فنيين ثلاثة حجوزات متزامنة. إن لم يوجد فنيون تكون السعة 1.
- **التوقيت:** المواعيد تُحسب بإزاحة ثابتة `SHOP_UTC_OFFSET` (الافتراضي `+03:00`). لا توجد مناطق بتوقيت صيفي في معظم الدول العربية، فإن احتجت غير ذلك فعدّل القيمة.
- **الإلغاء:** لا يوجد حذف للحجوزات، فقط تغيير الحالة إلى "ملغي"، حفاظاً على السجل.
- **التذكير:** يُعلَّم الحجز قبل الإرسال، فإن فشل الإرسال لا يُعاد تلقائياً. الهدف تجنب تكرار الرسائل.

## نشر الإنتاج

- ضع التطبيق خلف HTTPS (Nginx أو Caddy أو Cloudflare)، واضبط `TRUST_PROXY=true` ليُقرأ IP الحقيقي لحد المعدل.
- احفظ مجلد `data/` (ملف SQLite) وخذ نسخاً احتياطية منه.
- التطبيق عملية واحدة لأن المجدول وSQLite محليان. للتوسع انقل قاعدة البيانات إلى PostgreSQL وأبقِ المجدول في عملية واحدة.

## اقتراحات للتطوير

1. قوالب واتساب معتمدة، وحفظ حالة الإرسال في الحجز لعرض الفشل في اللوحة.
2. Cloudflare Turnstile بدلاً من التحدي الحسابي إذا تعرّض الموقع لهجمات حقيقية.
3. نوع الخدمة (صيانة، تركيب، تنظيف) كحقل في الحجز، وتقدير سعر أولي.
4. رابط للعميل لتعديل الحجز أو إلغائه برقم المرجع ورقم الجوال.
5. تعيين فني تلقائي حسب القرب الجغرافي، فالإحداثيات متوفرة بالفعل.
6. مراقبة الأخطاء عبر Sentry أو سجل مركزي، وأيقونات PWA مخصصة بدل المولّدة.
